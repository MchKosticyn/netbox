### Tags
`#dev`, `#python`, `#django`, `#sqlite`, `#udf`, `#collation`, `#debugging`, `#testing`

### Goal
Эмулировать PostgreSQL‑специфичные операции на SQLite с помощью пользовательских функций (UDF) и колляций, чтобы запросы/фильтры и тесты работали одинаково на обоих бэкендах.

### Scope
- Вносить правки только в центральные точки инициализации БД (регистрация UDF/колляций), в утилиты запросов (колляции/функции), и минимум в фильтры/поля, где это необходимо.
- Не изменять бизнес‑логику, только совместимость выполнения запросов (лукапы, аннотации, сортировка, regex, inet/cidr и т.п.).
- Если потребуется менять другие файлы, запросить подтверждение.

### Steps
1. Диагностика и таргетированные тесты
   - Запускать тесты строго группами и/или точечными кейсами, чтобы быстрее локализовать проблемы UDF/колляций.
   - Никогда не использовать `--keepdb`.
   - Никогда не запускать тесты в фоне.
   - Использовать повышенную детализацию (`-v 2`) и при необходимости `--failfast` для ускорения цикла.
   - Приоритезировать проблемные группы: сначала утилиты/фильтры, далее `dcim.tests` и `extras.tests` (эти группы могут падать, их нужно запускать отдельно и фиксировать ошибки по мере появления).

2. Инвентаризация необходимых UDF/колляций
   - Определить, какие функции нужны (примеры):
     - REGEXP/IREGEX: оператор `REGEXP` для лукапов `__regex`/`__iregex`.
     - INET/CIDR: `INET_CONTAINS`, `INET_CONTAINS_OR_EQUALS`, `INET_CONTAINED`, `INET_HOST`, а также `HOST`/`INET`/`FAMILY`/`MASKLEN` для трансформов.
     - Естественная сортировка: колляция `natural_sort` для «человеко‑дружественного» порядка.
     - JSON‑массивы/диапазоны (при необходимости): `ARRAY_CONTAINS`, `RANGE_ARRAY_CONTAINS` для фильтрации по JSON1.

3. Регистрация UDF и колляций
   - Добавить регистрацию в единый хук создания соединения (сигнал `connection_created`) и/или выполнить «ленивую» регистрацию непосредственно перед генерацией SQL (в вспомогательных `Func`/аннотациях), чтобы исключить ошибки «no such collation/function» в тестах.
   - Реализовать функции с безопасной обработкой ошибок (возврат 0/None при некорректном вводе), без побочных эффектов.
   - Для `REGEXP` реализовать обёртку на `re.search` и зарегистрировать как `REGEXP` и `regexp` (регистронезависимая резолюция в SQLite).
   - Для `natural_sort` реализовать сравнение «число/текст» с нечувствительностью к регистру текста.

4. Адаптация утилит запросов
   - В местах, где используются специальные колляции/функции (напр. вспомогательные `Func` для колляций), добавить гарантию регистрации требуемых сущностей на активном соединении перед генерацией SQL.
   - Обеспечить возможность передавать имя поля (строкой) — оборачивать в `F()` внутри утилит.

5. Минимальные точечные правки в фильтрах/полях (по необходимости)
   - Привести канонический формат данных к ожидаемому (например, формат MAC‑адресов), если это влияет на сравнения/regex.
   - Избегать переписывания логики — только нормализация представления и совместимость лукапов.

6. Проверка и итерации
   - Повторно запускать только те тесты/группы, которые падали, фиксировать результат «до/после» (сводка: количество упавших/пройденных).
   - Продолжать добавлять/уточнять UDF/колляции и адаптации до полного прохождения релевантных тестов.

### Как запускать тесты и собирать логи
- Команды:
  - `source .venv/bin/activate && python manage.py test <module_or_dotted_path> -v 2`
  - Примеры:
    - `bash -lc 'mkdir -p logs && source .venv/bin/activate && python manage.py test extras.tests.test_customfields.CustomFieldModelFilterTest.test_filter_date -v 2 --failfast | tee logs/extras_customfield_date_failfast.log'`
    - `source .venv/bin/activate && python manage.py test dcim.tests -v 2`
    - `source .venv/bin/activate && python manage.py test extras.tests -v 2 --failfast`
- Правила:
  - Никогда не использовать `--keepdb`.
  - Запускать тесты группами; большие наборы — по очереди (не параллельно, не в фоне).
  - Для длинных логов используйте `| tee <logfile>`:
    - `source .venv/bin/activate && python manage.py test extras.tests -v 2 --failfast | tee extras_failfast.log`
  - Хранить логи в корне проекта или в папке `logs/` и ссылаться на них в отчёте.
  - Группы, которые могут требовать доработок и часто падают: `dcim.tests`, `extras.tests`. Запускайте их отдельно и фиксируйте конкретные ошибки.

### Output
- Список добавленных UDF и колляций (название, назначение) и места их регистрации.
- Перечень изменённых файлов с кратким описанием правок.
- Сводка тестов: что запускалось, ключевые ошибки «до», и подтверждение «после` с путями к логам.
- Короткие комментарии по принятым упрощениям/нормализации данных (если применялись).
